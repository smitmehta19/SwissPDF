# Redaction leak fix (integ-1 #1, #2, #3, #7, #14): independent QA review

Date: 2026-10-27. Scope: `git diff HEAD` of `src/lib/redactOps.js`, `src/lib/formOps.js`, `src/tools/v2/redact.jsx`, `scripts/corpus-test/validate.mjs`, `scripts/corpus-test/cases.mjs` (branch wip-parity, uncommitted).

## Verdict: reject (not shippable as "destroys the content")

The integ-1 leaks that were reported are fixed: no orphan pages, no loose objects, no XFA, raster pages rewritten in place. Rows pass: 82 pass, 1 known unrelated fail. But the output still has recoverable redacted content through paths nobody tested. One of them is on a corpus row that currently PASSES (`g3-redact-form-value-fw9`): the redacted value is still drawn by a reachable appearance stream. The new raw check cannot see it because the text is a hex string.

P0: 7 · P1: 3 · P2: 2 · P3: 2

## Verified OK (with evidence)

- **Corpus:** `npm run test:corpus -- --case "redact|forms" --name review-redact` gave 82 pass, 1 fail (`forms-fill-xfa-imm1344e`, "found text fields to fill: 0"). The same failure is in every earlier scorecard since `2026-10-17-baseline`, so it is unrelated. Report: `docs/test-results/review-redact.md`.
- **leakCheck coverage:** "raw file clean" is present and passing on all 23 redact rows that write an output (from `review-redact.json`). The 2 `redact-find-split-*` rows are search-only.
- **Would fail on old code:** the old raster path (pdf-lib `insertPage` + `removePage` + `save`, replayed in Node on tracemonkey p1, p2, p4) gives `redactionLeaks` = "3 page object(s) outside the page tree", "66 unreferenced object(s)", and "dynamic" in orphan streams. The old code's own image path needs a browser (`?url` import), so the same steps were replayed. The old remove path (MuPDF) was already clean.
- **Real files, both methods, deep scan** (every object, decoded streams including hex and UTF-16, every Form XObject drawn on a scratch page, page text with OCGs forced on, true raw-byte stream inflate): `aws-invoice` "charges", `flipkart-invoice` "invoice", `pdfjs-tracemonkey` "dynamic", `rot90-cropbox-bert` "language", `pdf20-incremental-save` "Words", and the synthetic `redact-secretname`. No hits. Positive control: the same scanners find the term in every input (tracemonkey 17 non-page hits, rot90 31, and so on).
- **XFA:** `xfa-imm1344e-filled.pdf` whole-page redaction, both methods: Leonhard, Euler, Brunswick, Gauss and Osthoff are gone from every object and every raw stream; `/XFA` is gone. The datasets stream (obj 73, `/Type/EmbeddedFile`) is gone.
- **Incremental save:** `pdf20-incremental-save` input has 2 `%%EOF`; both outputs have 1, and there is no term in any inflated raw stream.
- **Geometry, image mode:** a raster at the native 2.5x scale against the input render gives a mean grey difference of 0.05 (rot90-cropbox) and 0.00 (c-rot270-cropbox) at offset 0,0, and 10 or more at a 1 px shift: exact alignment. Inside the term boxes 100% black on rot90-cropbox-bert, c-rot270-cropbox and c-rot180-origin, both methods. In remove mode, outside the boxes, at most 0.003% of pixels differ.
- **Scanned page, remove mode:** `darwin-origin-of-species-ia.pdf` box region is white in the image after redaction (render with the overlay stripped).
- **Images under a box** (direct, inside a Form XObject, inline BI/ID/EI, with SMask): removed or blanked in remove mode. Image mode leaves only the page raster.
- **Fully covered filled compound path:** removed.
- **formOps field counts** (direct `fillFields` and `flattenForm` in Node): fw9 23 widgets in and 23 after fill, 23 flattened to 0 left; i485 730/730, 730 flattened; f1040 199/199, 199 flattened. 0 loose objects and 0 XFA streams in every output. Corpus rows `forms-list-*` (23 / 730 / 199), `forms-flatten-i485` (730) and fill rows pass.
- **UI result note** (`redact.jsx:254-265`) matches `res.cleaned` for the synthetic file: properties 2, XMP, bookmark 1, comments 2, attachment 1, alt texts 2.
