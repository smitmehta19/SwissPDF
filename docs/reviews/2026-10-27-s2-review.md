- IndexedDB quota errors: not simulated. Code downgrades to memory on a failed write (`downgrade`), outputs are written before the flags that hide inputs, so a failed write should not hide inputs; not run.
- Two tabs on the same workspace (IndexedDB `onversionchange`, concurrent writes): not run.
- Screen reader behaviour (NVDA/VoiceOver) of the tabs, palette combobox and live regions: checked from markup only.
- Firefox and Safari: Chromium (Playwright) only.
- Screenshots / visual design at 1440 and 390: ran s2-ui with `--no-shots` (to keep the author's screenshots); layout checked only through the s2-ui assertions (no horizontal scroll, bar inside the screen).
- Reader memory: only the window of pages around the current one is kept (1 image kept in the 956-page run), but canvas release inside `renderPageImage` was not checked, and `performance.memory` (239 MB both times) is too coarse to prove anything.
- Duplicate-then-undo selection state: code read only (a selected duplicate stays in `sel` after Undo, so the "Clear (n)" count can include a tile that is gone); not worth a finding without a run.
