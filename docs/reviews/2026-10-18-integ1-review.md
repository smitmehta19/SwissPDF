# Integration 1: independent QA review

Date: 2026-10-18. Scope: uncommitted main tree after integration 1 (U1 + U2a + U2b/U3 + U4): `src/app`, `src/tools/v2`, `src/lib`, runner. Claimed: 573/577 corpus (`docs/test-results/integ-1.md`).

**Verdict: reject until the 2 P0 are fixed.** Redaction, the tool sold as "destroys the content", leaves the removed content in the output file on two paths. Five P1s: data loss in the workspace store, wipe that does not wipe, HTML sanitizer network bypasses, and more redaction and form leaks. The rest of the shell, the convert tools and the runner are in good shape (all UI scripts pass, no document bytes leave the page).

Severity: P0 = ship blocker, P1 = fix before release, P2 = fix this phase, P3 = backlog.

## Verified OK (with evidence)

- **Build**: `npm run build` OK (22.6 s), only chunk-size warnings.
- **Corpus, quick, 4 shards** (`docs/test-results/review-integ1.md`): 119 pass, 1 fail. The fail is the known U3 row `compare-inserted-page`. Health row: 44 checks, 0 failed.
- **Built app under /SwissPDF/** (`serve-pages-sim.mjs`, no COOP/COEP headers, isolation by coi-serviceworker):
  - `health.mjs`: all pass.
  - `chain.mjs`: 12/12 (merge, compress carry-over, reload keeps v3, undo, cancel, page editor, wipe, ops in the worker, no page errors).
  - `g3-chain.mjs`: 10/10 (forms fill, page numbers, redact of the typed value and a phrase, version 4).
  - `g1.mjs`: 12/12, including the 956-page every-page split (split 17 s, zip 5 s, 62 MB).
  - `g4-ui.mjs --no-shots`: 23 pass, ALL PASS (JPG/HEIC/TIFF to PDF, compress, PDF to Word, PDF to images with JBIG2, Word to PDF through the pinned engine, HTML, Markdown).
- **Dev server**: `ui-frame.mjs` 9/9 (crop, edit, sign, redact, page numbers, forms on rotated and offset pages).
- **Privacy / network**: every request of all runs above logged at browser-context level (pages, frames, workers). Zero non-GET requests anywhere. Off-origin hosts: only `cdn.zetaoffice.net` (the 4 pinned engine files) and `cdn.jsdelivr.net` (Tesseract, #9). No document bytes leave the page. Crop, edit, sign, redact, page numbers, forms, merge, split, compress: no off-origin request at all.
- **Redact Remove path, non-fallback pages**: MuPDF save uses `garbage=compact`, the old content streams are gone. Widget values under a box are cleared (fw9 row and g3-chain check raw bytes).
- **Sanitizer**: blocks plain `<img src=http>`, `url(http...)` in style attributes and `<style>`, SVG `<image href>`, `<feImage>`, and the quoted-paren trick. No script runs (sandbox without allow-scripts).
- **LibreOffice engine**: one instance per page via `globalThis.__swisspdfLibreOffice`; all 4 files size and SHA-256 checked on download; the frame only gets blob URLs and checked buffers; a hung job kills the frame (`resetEngine`) and fails pending jobs; jobs run one at a time.
- **Jobs / worker**: arguments are structured-cloned in and results transferred out, so page-side caches stay valid; Cancel terminates the lane worker and rejects in-flight calls; a worker that fails to load falls back to inline.
- **Dialog**: focus goes to the first (safe) button, Tab is trapped, Escape closes, focus returns to the opener.
- **U1 review follow-ups present in code**: per-character font coverage with a clear error (`fonts.js:123-220`), MuPDF docs destroyed in `cryptoOps.js`, thumbnail release generation (`pdfText.js:129-133`).
- **Zip**: entries are read lazily from Blobs, duplicate names get " (2)", output names come from range labels (no path parts).

## Not verified

- LibreOffice Cancel (#8) was not timed in the browser; it follows from the code.
- Sanitizer bypasses ran with the app's own `sanitizeHtml` and `renderFrame` in Chromium, not by pasting into the UI. The hi-fi path calls the same `renderFrame`, so the requests fire there too.
- `layout.js` edge cases (spread of very large arrays into `Math.min`, degenerate pages): read only, not fuzzed.
- Memory over a long mixed session, Firefox and Safari, and #25.
- Full 577-row run not repeated (quick subset only).
