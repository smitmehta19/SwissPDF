## Architecture limits

- **Main thread:** pdf-lib and MuPDF (WASM, synchronous calls) run on the UI thread (lib/mupdfOps.js:6-8, lib/cryptoOps.js:3-5, all pdf-lib ops). Large saves freeze the tab with no repaint or cancel. Only pdf.js and Tesseract use workers. Move pdf-lib + MuPDF into a dedicated worker (Comlink), transfer ArrayBuffers instead of copying.
- **Memory:** whole-file ArrayBuffer kept per item plus a throwaway pdf-lib parse at intake just for page count (components/usePdfFiles.js:22-24); `bytes.slice(0)` copies on every pdf.js and MuPDF call (lib/pdfText.js:26, lib/mupdfOps.js:18,36, lib/cryptoOps.js:24,42,73,98); pdf.js doc reopened per page; outputs, ZIP and thumbnails all in RAM. Practical ceiling today is roughly 100-200 MB input, far from 500 MB / 1000 pages. Fix: one open handle per engine per file, page-count via pdf.js (lazy, cheap), streaming output.
- **pdf-lib as core engine:** no decryption, weak damaged-file tolerance, no font shaping, drops document-level structures on copy. Keep it for drawing, but route structure work (merge/split/decrypt/repair/linearize/object streams) through **qpdf-wasm** or MuPDF.js, which preserve outlines, forms and links.
- **Missing libs/assets:** qpdf-wasm (structure-preserving page ops, decrypt, linearize); `@pdf-lib/fontkit` + self-hosted Noto subsets (non-Latin text); pdf.js `cmaps`, `standard_fonts`, `wasm` assets; self-hosted Tesseract core/worker/lang data; client-zip (streaming ZIP); EXIF reader for images; optional PAdES signer.
- **Lazy loading:** heavy engines are dynamically imported (good: mupdf, tesseract, docx, xlsx, pptxgenjs, LibreOffice). But every tool component is imported statically in tools/registry.js:1-27 and pdf.js + pdf-lib load in the main chunk. Use `React.lazy` per tool to cut first load.
- **External network at runtime:** Tesseract assets (jsDelivr) and LibreOffice (`cdn.zetaoffice.net`, unpinned "latest") are fetched from CDNs; files stay local but "works offline" is not true for OCR / HiFi Office, and an upstream "latest" change can break conversion.
- **Coordinate model:** no single "visible page frame" abstraction (rotation + CropBox + MediaBox origin). Each tool mixes pdf-lib unrotated sizes with pdf.js rotated viewports, which is the root cause of findings 2, 8, 11, 13. One shared helper fixes the whole class.
